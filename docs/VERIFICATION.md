# 검증 기록

최신 기록표 개편(2026-10-23): [BMAD 설계·토의·검증 기록](design-thinking-record-sheet-2026-10-23.md). 51개 테스트·타입/린트/빌드와 개발/프로덕션 미리보기의 Chrome 검증을 완료했다. 아래는 2026-10-21 감사의 기존 상세 기록이다.

검증일: 2026-10-21 (Asia/Seoul). 작업 시작의 `main`은 깨끗했으며 기존 사용자 변경은 없었다. 이 문서는 테스트 코드 실행, 실제 UI 조작, 모의 클라우드 검증을 구분한다.

## 실행한 BMAD 워크플로

설치된 `bmad`의 `knowledge.py --content`로 관련 스킬·모듈을 확인하고, Design Thinking의 사용자 여정·문제 정의·대안 비교·실제 프로토타입·관찰 검증과 Problem Solving의 Five Whys·Failure Mode·PDCA를 수행했다. 마지막에는 Party Mode의 기본 `code-review-crew`를 session 모드로 적용했다. 별도 서브에이전트나 사용자 인터뷰를 수행했다고 주장하지 않는다.

프로젝트 자체 `_bmad/config.toml`은 없다. 설치된 기본 스킬과 resolver를 사용했다. 상세 과정은 [Design Thinking](design-thinking-final-quality-2026-10-21.md), [Problem Solving 및 최종 감수](problem-solution-final-quality-2026-10-21.md)에 남겼다.

## 실제로 재현해 수정한 문제

- 시작 초안의 `memories:null`에서 `filter` 호출 오류로 앱이 빈 화면이 됐다. 시작·집필·게임 입력 경계를 각각 검증한다.
- 경험 삭제 확인창이 편집창 뒤에 가려지고 두 초점 잠금이 동시에 실행됐다. 한 대화상자만 표시하고 취소 시 편집으로 돌아온다.
- 기기 쓰기 실패에도 ‘자동 저장’으로 표시했다. 실제 저장 실패·재시도와 초안 실패를 별도로 표시한다.
- 복구본과 이전 초안은 저장만 되고 접근하는 화면이 없었다. 복구함·손상 원문 다운로드·JSON/Markdown 보관을 연결했다.
- 초안이 전역 키에 묶였다. 인물 고유 ID·사건·방문·대체·시즌별로 보관한다. 기존 전역 초안과 이전 초안도 이관한다.
- 체크한 기술이 잃은 기술과 같은 취소선이었다. 상실만 취소선으로, 사용은 읽을 수 있는 상태로 표시한다.
- 빠른 게임의 연대기 빈 화면이 ‘사건마다 기록이 쌓인다’고 안내했다. 실제 방식에 맞는 설명과 기억으로 가는 경로를 제공한다.
- 가져온 기억 ID 대신 도구의 고정 `m1/m2`가 전달될 수 있었다. 실제 기억 목록에서 유효한 대상을 고른다.
- 클라우드는 캐시를 서버 확인으로 오인하거나 다른 기기의 쓰기를 덮어쓸 수 있었다. 서버 확인과 거래 안의 재확인을 수행하며 충돌 때 선택한다.
- 복구본을 저장할 수 없는 충돌에서는 양쪽 파일 다운로드·동기화 중단 후 기기에서 계속하기가 가능하다.

룰북 PDF 16·17·24·26쪽을 재확인했고 기술 사용/상실, 비용 대체, 일기장, 두 기록 방식의 표현을 대조했다. 기존 사건·결말 카탈로그와 룰 엔진은 보존했다. 수동 주사위 결과 입력이 있다고 쓰여 있던 문서는 실제 기능에 맞게 정정했다.

## 실제 Chrome의 UI 조작

`http://127.0.0.1:5176/`의 개발 서버를 독립 Chrome 프로필에서 Playwright로 조작했다. 실제 사용자 저장소·Google 계정은 사용하지 않았다. 뷰포트가 실제 기기·운영체제 테스트를 대신하지는 않는다.

- 예시 생성, 시작 초안 JSON/Markdown 다운로드·재가져오기, 손상된 부가 초안에서 현재 정보 유지.
- 긴 글·한 문장 경험의 새로고침 복원, 기술 추가·체크·해제, 규칙상 사용/상실 표시.
- 경험 삭제의 확인·취소, 잘못된 입력의 오류와 편집 유지, 입력 초점·Tab/Shift+Tab 순환·Escape·열기 버튼으로 복귀, 배경 inert.
- 기억 이관, 일기장 네 기억 한도, 책별 기억·소속 이름, 책 분실 뒤 모든 기억의 읽을 수 있는 보존.
- 경험과 연대기 기록 완료 → 주사위 이동, 연대기 수정, JSON/Markdown의 실제 파일 다운로드·내용 확인.
- 다른 사건으로 이동할 때 초안 분리, 복구함에서 이어쓰기, 가져오기 전 기록·초안 백업 및 재복원.
- 손상된 시작·집필·게임 데이터, 원본 보관 및 다운로드. `QuotaExceededError`를 주입해 실패 표시·재시도를 확인.
- 가져온 기억 ID의 예외 용량 변경, 대체 사건 선택·재로딩 유지·기본 복귀.
- 모바일 빠른 게임 완료와 정확한 빈 상태, 잃을 기술이 없는 비용에서 최후·끝난 기록표 변경 차단·최후 문장 수정.
- 평화 결말, 잘못된 다음 시즌 입력의 오류 유지, 새 특성 입력, 같은 인물의 사건 0 재개·이력·추가 공간 보존.
- 주요 9화면(이야기·기억·기술·자원·인물·표식·일기·연대기·규칙)을 1440/1024/768/390/320px에서 순회했다. 긴 한영 콘텐츠·큰 용량 숫자를 포함해 문서 가로 넘침이 없었다.
- Geist/SUIT 로컬 로드, 모바일 기억 접기, 최종 데스크톱·모바일 스크린샷을 확인했다. 실행 시나리오의 런타임 JavaScript 오류는 없었다.

주요 흐름 13묶음, 추가 경계 흐름 8묶음을 실행했다. 이는 관찰한 시나리오의 묶음이며 모든 가능한 입력·기기를 전수 검증했다는 의미는 아니다.

감사용 실행 스크립트와 결과는 작업 호스트의 `/tmp/tyov-final-audit/`에 있다: `flows.mjs/json`, `edges.mjs/json`, `baseline.mjs/json`, `final-desktop.png`, `final-mobile.png`. 임시 파일이며 배포 번들이나 저장소에 포함하지 않는다.

## 실제 훅 + 모의 Firebase 전송

별도 Chrome에서 Vite가 제공하는 실제 `useGameSave.ts`의 Firebase import만 모의 auth/Firestore 모듈로 치환했다. 앱 코드에 테스트 전용 플래그나 모의 기능을 넣지 않았다. 다음 6묶음에서 실패·충돌 분기와 쓰기 횟수·내용을 확인했다.

1. 캐시만 보이는 동안 쓰기 0회, 서버 확인 후 충돌 선택·양쪽 복구본, 변경 저장.
2. snapshot 확인과 transaction 읽기 사이 다른 기기가 수정하면 덮어쓰기 0회, 명시 선택 후 저장.
3. 쓰기 실패 때 기기 기록 유지, 실제 저장 실패 표시, 같은 서버 기준을 유지한 재연결·재시도.
4. 손상된 서버 기록에 덮어쓰기 0회.
5. 계정 전환 뒤 이전 계정 요청 완료가 새 계정 상태를 동기화 완료로 바꾸지 않음.
6. 복구본 쓰기 실패 시 오류와 선택창 유지, 클라우드 원본 파일 다운로드, 로그아웃으로 동기화를 멈춘 뒤 기기에서 계속하기.

충돌 선택 전 기기 파일 내보내기 창을 열고 닫으면 충돌 선택으로 돌아오는 경로도 확인했다. `cloud.mjs/json`은 같은 임시 폴더에 있다. 클라우드 비교표·내보내기 대화상자도 390/320px에서 가로 넘침 없이 표시되는 것을 추가 확인했다. 이 검증은 실제 Google OAuth·Firestore 서버 권한·실제 네트워크 거래의 통합 검증이 아니다.

## 유지한 디자인과 한계

검정 제본 같은 탐색부, 버건디, 밝은 종이, Geist/SUIT와 집필 중심 병치·모바일 기억 접기를 유지했다. 연대기는 본문 폭과 문단 리듬을 가진 문서로, 일기장은 책 소속이 드러나는 구성으로 다듬어 반복 관리 카드 형태를 줄였다. 용량 점·방문·소실 표시는 실제 의미가 있어 유지했다. 새로운 장식 그림·서체·그라디언트는 추가하지 않았다.

- Google 실계정 로그인, 실제 Firestore 권한·동기화, 원격 자동 배포 성공은 확인하지 않았다.
- 실제 모바일 Safari·Android 기기·스크린리더 장비는 사용하지 않았다. Chrome에서 키보드·레이블·설명 연결·inert 동작을 확인했다.
- 집필 초안은 기기/JSON 보관 대상이다. 클라우드에는 완료한 게임 상태가 동기화된다. 브라우저 데이터 삭제를 견디는 보관은 별도 파일 백업이 필요하다.
- 기기 복구본은 각 항목의 최신 한 개이고 버전 관리 서버가 아니다. 이전 집필 초안은 별도로 유지한다. 현재 인물 JSON은 다른 인물의 복구함 전체를 포함하지 않는다.
- 여러 로컬 탭의 동시 편집을 병합하는 기능, 다인 캠페인 서버, 자연어 사건의 자동 판정은 제공하지 않는다.
- 주 번들 크기 안내는 남아 있다. 이번 작업에서 기능 보존과 검증된 저장 경계 수정을 우선했고 SDK 분할은 하지 않았다.
