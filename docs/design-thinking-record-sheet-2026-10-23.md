# Design Thinking · 칸이 보이는 흡혈귀 기록표

날짜: 2026-10-23 / 진행: Codex / 상태: 구현·검증 완료

## Design challenge

사용자는 ‘기술의 칸이 3개로 분리’되어 소유·사용·소실을 이해하고 조작하기 쉬운 인터페이스를 원한다. 기존 디자인 보존 의무는 없고, 신비로운 분위기를 원하되 AI 생성 이미지는 사용하지 말라고 명시했다. 최근의 저장·복구·룰 엔진은 보존하고, 기록표와 창조/집필 여정의 표현을 바꾼다.

설치된 `bmad-party-mode/SKILL.md`, 기본 `customize.toml`과 roster resolver, `bmad-cis-design-thinking/SKILL.md`, `design-methods.csv`, `template.md`를 실제로 읽었다. 프로젝트 `_bmad` 설정은 없으며 설치된 공통 resolver와 기본값을 사용했다. 커스텀 hook·persistent facts는 없다. 출력은 `docs/`로 정했다. 사용자 지시 ‘알아서 진행 후 푸시’에 따라 대화형 승인 체크포인트는 진행 보고·문서 저장으로 대체한다.

## EMPATHIZE

자료: 이 대화의 실제 요구, 현행 코드·룰북 대조표, 독립된 UX/규칙 검토. 방법은 Journey Mapping·Empathy Mapping·Jobs to be Done이다. 새 사용자 인터뷰나 여러 명의 사용자 시험을 수행하지 않았다.

| 여정 | 마찰 | 기대 |
| --- | --- | --- |
| 인물 창조 | 세 기술·자원이 각각 한 textarea의 줄바꿈 규약에 숨어 있음 | 실제 세 개 입력칸, 정착 여부는 체크박스 |
| 사건 읽기 | 기억만 옆에 있고 기술/자원 조작은 페이지 왕복 | 현재 사건을 남겨 두고 기록표 항목 전환 |
| 사용 | 사용과 상실이 목록 안에 섞임 | 사용한 기술은 소유한 상태로 식별 |
| 소실 | 잃은 물건이 현재 목록에 계속 남음 | 현재 소유물에서는 빠지고, 흔적은 따로 열람 |
| 모바일 | 여덟 탐색 항목·보관 도구를 가로 스크롤해야 함 | 이야기·기록표·연대기와 기록표 항목 선택 |
| 분위기 | 일반 업무 앱 같은 평면적 화면 | 오래된 기록의 활자·먹색 표지·미색 기록면 |

Empathy map: ‘칸을 분리하고 편의를 고려’, ‘신비로움은 필요하지만 생성 이미지는 싫음’은 직접 발언이다. 소실의 의미를 현재 소유물과 분리하고 싶다는 해석은 게임 맥락과 발언에 근거한 설계 추론이다.

## DEFINE

POV: 솔로 플레이어는 지금 가진 것, 사용한 것, 잃은 것을 별개의 자리로 이해해야 한다. 이 구분이 다음 비용·기록의 선택에 실제 영향을 주기 때문이다.

HMW: 어떻게 세 가지로 시작한다는 것을 보이면서도 게임 중 획득을 막지 않을까? 어떻게 소실이 실제로 느껴지면서 기록은 보존할까? 어떻게 이미지 없이 신비로움을 만들고 긴 한국어 문장을 편하게 읽게 할까?

제약: 기술·자원 셋은 창조 조건이지 최대치가 아니다. 체크 기술은 소유한 기술이다. 잃은 데이터와 ID를 지우거나 새 항목으로 덮어쓰지 않는다. 일기장도 자원 수에 포함한다. 기존 JSON·초안 형식은 유지한다.

## IDEATE

방법: SCAMPER Design·Analogous Inspiration(수기 기록표, 도서관의 서지·목록)·Brainstorming.

검토한 18가지 안: (1) 세 개 개별 입력 (2) 정착 체크박스 (3) 필멸자 추가 칸 (4) 번호 있는 기술 슬롯 (5) 번호 있는 자원 슬롯 (6) 무제한 추가 칸 (7) 현재/소실 분리 (8) 사용 상태 인쇄 표식 (9) 소실 확인 (10) 지시 모드의 복구 제어 (11) 기억의 빈 경험 자리 (12) 기억에서 바로 글쓰기 (13) 사건 옆 기록표 탭 (14) 모바일 세 가지 주요 화면 (15) 보관 도구 메뉴 (16) 마루 부리 서사 활자 (17) 먹빛·미색·적색 (18) 실제 사건/권/쪽 정보의 편집 위계.

제외: 고정 3개 최대치, 상실 데이터 삭제, AI 생성 이미지, 별자리·룬·장식 인장, 배경 애니메이션, 읽기 어려운 가짜 고딕 서체, 저장 스키마의 불필요한 변경.

선택한 세 묶음: **개별 입력과 가변 기록 칸**, **현재와 소실·사용의 구분**, **집필 곁 기록표와 이미지 없는 서책 문법**.

## PROTOTYPE

실제 코드로 창조 입력, 가변 기록표, 소실 아카이브, 기억 경험 자리, 곁 기록표 탭과 모바일 탐색을 만든다. Role Playing으로 ‘초기 셋 → 체크 → 상실 → 넷째 획득 → 재로드 → 지시로 복구’, 책 분실, 모든 항목 소진, 작은 화면과 키보드 경로를 검증한다.

## 실제 구현·반복 결과

- 창조의 기술·자원·필멸자는 개별 입력칸이다. 자원의 정착 여부는 별도 체크박스이고, 저장은 기존 줄 형식과 호환한다. 필멸자는 넷째 이후도 추가할 수 있다.
- 현재 기술·자원은 각각 번호 있는 독립 칸이다. 세 개는 시작 수량이며 획득 개수의 상한이 아니다. 실제 원본 순서에 따른 번호·ID를 유지하고 빈 자리는 표현용 placeholder일 뿐 실제 데이터에 빈 항목을 만들지 않는다.
- 체크 기술은 현재 칸에 남는다. 상실한 기술·자원·표식과 죽은 인물은 소실 흔적에 보관한다. 복구하면 같은 ID·사용 상태로 돌아온다. 기술 상실·죽음에도 확인창을 제공하며, 복구·표식 변경은 사건 지시 모드와 맞춘다.
- 기억은 기본 세 경험의 채운/빈 자리를 보여 준다. 기억 화면에서 선택한 칸의 경험 입력으로 곧바로 이동한다. 큰 예외 용량은 숫자를 쓰고 대량 DOM을 만들지 않는다.
- 이야기 곁 기록표는 기억·기술·자원 탭으로 전환한다. 탭 화살표·Home·End·선택 상태·초점 이동을 구현했고, 기술을 체크한 뒤 버튼이 사라져도 초점이 해당 칸에 남는다.
- 모바일은 이야기·기록표·연대기와 기록표 항목 선택으로 탐색한다. 보관·도움말 메뉴는 Escape로 닫을 수 있다.
- 서사와 제목에는 네이버 공식 배포의 Maru Buri를 로컬로 추가했다. 조작·입력은 Geist/SUIT를 유지한다. 먹색 표지·미색 기록면·짙은 적색과 실제 사건/방문/권 정보를 사용하고 생성 이미지·배경 텍스처·별자리·룬을 추가하지 않았다.

독립 UX 검토로 두 회귀를 수정했다. 자원 필드를 매번 trim하여 단어 사이 공백이 사라지던 문제는 입력 중 공백 보존과 제출 경계의 정리로 분리했다. 바로가기가 화면만 이동하던 문제는 선택된 탭으로 초점도 보내도록 고쳤다. 새 개별 입력과 맞지 않는 ‘한 줄에 하나씩’ 안내도 바꿨다.

## 검증

- `npm test`: **51개 통과**. 기존 42개와 슬롯·시작 입력·정착 접두사·문자별 공백 입력 회귀 9개다.
- `npm run lint`: TypeScript 미사용 선언·ESLint·React Hooks 검사 통과.
- `npm run build`: 성공. 주 JS 번들 약 798KB / gzip 235KB이며 기존 500KB 크기 안내는 남아 있다.
- `git diff --check`: 통과.
- 실제 Chrome의 독립 프로필에서 **개발 서버 5176과 프로덕션 미리보기 4176**을 조작했다. `tests/browser/record-sheet.mjs`의 10개 흐름 묶음이 통과했고 런타임 JavaScript 오류는 없었다. 9개 주요 화면을 1440/1024/768/390/320px로 순회하고, 긴 한영 이름·경험·기억 주제·큰 용량에서도 가로 넘침이 없었다.
- 개별 입력의 새로고침, 체크→상실→넷째·다섯째 획득→동일 ID 복구와 체크 유지, 곁 기록표/키보드, 선택 기억에서 집필·완료·이동, 일기장 자원 분실, 인물/표식 권한, 비용 소진의 최후, 보관·재가져오기와 폰트 로드를 확인했다.
- 기존 실제 저장 훅 + 모의 Firebase 전송의 6개 시나리오도 재실행해 통과했다. 실서버 검증으로 간주하지 않는다.
- 배포용 데스크톱·모바일 스크린샷을 직접 읽어 활자·색·칸의 구획과 배치도 확인했다. Chrome의 전체 페이지 캡처는 상단으로 스크롤하고 다음 렌더 프레임을 기다려 기록한다.

브라우저 실행 예시(Playwright가 설치된 환경):

```sh
PLAYWRIGHT_MODULE=/absolute/path/to/playwright/index.mjs \
BROWSER_EXECUTABLE=/absolute/path/to/chrome \
APP_URL=http://127.0.0.1:4176/ \
node tests/browser/record-sheet.mjs
```

`AUDIT_OUTPUT`을 지정하면 결과 JSON·다운로드·스크린샷을 그 폴더에 보관한다. 미지정 시 OS 임시 폴더를 만든다. 이번 결과는 `/tmp/tyov-slots-2026-10-23/`와 `production/`에 있다. 기본 npm test에는 브라우저가 필요하지 않다.
